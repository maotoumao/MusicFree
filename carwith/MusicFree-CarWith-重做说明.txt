--------------------------------------------------------------------------------
一、功能
--------------------------------------------------------------------------------

总设定（本文全部改动的第一句，也是验收的第一条）：

      **没连着 CarWith，或者设置里的开关没勾 —— 上游行为逐字不变。**

落到代码上是三处硬门：
  1) CarWithLyric.decorate() 第一句 `if (!(connected && enabled)) return base;`
     —— 连着且勾着才新建 Builder 改写；否则把 kotlinaudio 自己那份原样交回。
  2) CarWithState 的 5 秒心跳只在两把开关至少一把勾着时才排程；全关着时连虚拟屏都不枚举。
  3) JS 侧 pushLyricState() 开头 `if (!lyricEnabled) return;`，不勾就一个字节都不发。
  4) Java 侧 publish() 上还有一位 dirty：从没贴过键（没勾开关、也没连过车机）时
     直接早退 —— 不装 provider、不碰 connector、一次 setMetadata 都不发，
     播放路径上等于没打过补丁。真贴过键才需要那一次「把键洗掉」的收尾重发。
  ★ 这条设定是给「万一适配错了」兜底的：门在，最差也只是车机没歌词，不会把手机端播放搞坏。
     （dirty 是后加的：v1/v2 的 attach 无条件装过 provider，撞上「四、构建」末尾
       运行期踩坑登记那条 8)，两把门叠在一起才是现在这个行为。）

1.1 车机投屏歌词（设置 → 歌词 → 车机投屏歌词（CarWith））

  键名由车机侧定死（CarWith_4.0.20 反汇编 + 真车实测），一个字符都不能改：

      ucar.media.metadata.LYRICS_WHOLE    整首标准 LRC，车机**首选**，它自己按播放位置排行
      ucar.media.metadata.LYRICS_LINE     当前句，只在整首解析不出来时兜底
      ucar.media.metadata.LYRICS_STATUS   "0" = 有词；"1"/"2"/"3" 一律当无词
      android.media.metadata.LYRICS       框架已知键，值与 LYRICS_WHOLE 相同（顺手给上）

  四条硬规矩（前四份文档踩过的坑，这里逐条落地）：

    (a) **每次换句都要重发整个 metadata。** 车机只在收到新 metadata 时才重读歌词，
        歌词行自己不会动。MusicFree 这一路是 lyricManager 的进度回调（RNTP 的
        progressUpdateEventInterval = 1 秒）→ JS → TrackPlayerModule.setCarWithLyric
        → CarWithLyric.update() → mediaSession.setMetadata()。
        ★ 逐句这一路必须**绕开** kotlinaudio 的自动更新：它开着
          setMetadataDeduplicationEnabled(true)，按 mediaId 去重，同一首歌不会再发第二次，
          所以只挂 provider 是推不动的，必须直接 setMetadata()。
    (b) **没词要显式清空。** 上一首的歌词留在会话里，车机就一直停在那一句。
    (c) **整首要算准偏移。** LrcParser.getPosition() 里减了 meta.offset，
        也就是 item.time 是不含偏移的原始时间；车机拿整首和真实播放位置比，
        所以推整首时必须 `item.time + offset` 加回去。漏了这条，偏移一开就是满屏对不上。
    (d) **整首有长度上限。** 车机读的是**一整个** metadata Binder 事务，同一份里还装着封面
        位图（400×400 ARGB ≈ 640 KB），超了限丢的是整包（连封面一起没）。
        这里定 MAX_WHOLE_CHARS = 24000（≈ 48 KB UTF-16，两份键共 96 KB，加位图仍在一包里），
        超限发**空串**而不是截断 —— 截断出来的半截 LRC 车机会照着排，最后一句永远对不上；
        发空串则退回 LYRICS_LINE，逐句还在走。

    清空策略这里和前作**不一样**，不是谁写错了：
      · 洛雪那条 smali 路复用同一个 Builder 对象 ⇒ 必须显式 putString("", "") 才洗得掉；
      · MusicFree 每次发布都 new 一个 Builder（上游 getMediaMetadataCompat() 就是新建的）
        ⇒ 想要「没有这个键」就不写它，想要「有键但为空」就写空串，两者都洗得掉上一首。
      本文选「连着且勾着」时重建整份、不写三个 *_URI，断开/关开关时原样交回上游那份。

1.2 封面（连着车机时）

    · 不发布 METADATA_KEY_MEDIA_URI：CarWith 一见 mediaUri 就去扒音频文件内嵌封面，
      扒不到也不再回落到位图 ⇒ 车机永远空白。
    · 这一份里已经带到位图时，ART_URI / ALBUM_ART_URI / DISPLAY_ICON_URI **三个一起断**。
      车机取图优先走 description.getIconUri()，而 iconUri 是这三个键级联出来的，
      只断一个还有两个顶上。
    · 一份 metadata 只带**一张**位图：上游同时把同一张图塞进 ALBUM_ART 和 DISPLAY_ICON，
      两张 400×400 同装是 Binder 超限的头号来源，这里只留 ALBUM_ART。
    · 全程 Compat → Compat：MediaMetadataCompat 进、MediaMetadataCompat 出，
      不经 Parcel 往返（前作实测：往返一次 400×400 会被压成 1×1）。

1.3 车机深浅色（设置 → 主题 → 跟随CarWith车机深浅色）

    · 读数：Settings.Global 的 ucar_night_mode，0 浅色 / 1 深色 / 读不到 -1。
      这个键本就是 CarWith 写给第三方读的，不需要权限，不动清单。
    · ★ 断开时系统不会把它清零 ⇒ 残值一律不采信：只在 connected 为真时读，
      断开直接记 -1（代码里 `if (nowConnected) readNight(ctx) else -1`）。
    · ★ ContentObserver 必须留强引用（挂在字段上）。只存在局部变量里会被 GC 掉，
      之后系统不再通知，表现是「车机翻灯，手机再也不跟」。
    · 心跳 5 秒一轮兜底（个别 ROM 不发 onChange），观察者 + 心跳双保险。
    · 只在**上一次真正应用过**的值翻了才动作（appliedDark 那条判定），不是「本轮开头算一次、
      结尾再算一次」——那种写法两次现算之间原生状态一变就两边相等，这次翻转谁也报不出去。
    · ★ 车机深浅色只改内存里的那份主题，**一个字都不写 Config**：断开或关开关后
      restoreStoredTheme() 就回到用户自己选的档。自定义主题在车机浅色档下临时落到内置浅色。

1.4 连接判据

    同时满足才算连着：
      1) 手机上有非 DEFAULT_DISPLAY 的虚拟屏，屏名含 com.miui.carlink 或 com.xiaomi.ucar.minimap；
      2) Display.getType() == 5（虚拟屏）。
    ★ type 这层必须反射取：getType() 不在公共 android.jar 里，Kotlin 直接引用会
      Unresolved reference，构建挂在 :app:compileReleaseKotlin；反射被 ROM 拦了就退回只判屏名。
    ★ 只判屏名会把录屏/投屏/平行视窗的虚拟屏误判成已连接；
    ★ 屏名里别去匹配 com.autonavi.minimap —— 那是 CarWith 内嵌高德的资源 ID，不是屏名。
      （check_apk.py / check_apk.ps1 里专门反向断言了这个串不在 dex 里。）
    任何读数失败一律按「没连着 / 读不到」处理，绝不向调用方抛异常。

1.5 数据来源与能力边界

    · 歌词就是 App 内歌词页那一份：插件 getLyric、自动搜词、本地歌词、歌词偏移全都复用，
      App 里没词 ⇒ 车机上就是无词，不做第二套取词逻辑。
    · 只出主行，不带译文（车机一屏一行，带译文会把行高挤掉）。
    · 熄屏后台可用：逐句靠的是 RNTP 原生定时器发的事件，和状态栏歌词同一条路，
      上游那条路本来就是熄屏可用的。
    · 不做标题反推（前作里 lx 那条路要靠曲名去搜词）：MusicFree 的标题就是真曲名，
      词也是插件给的，没有这一层。
    · iOS / 鸿蒙上整块不出现：原生模块不存在时 JS 全部空转，设置里两行也不渲染。

二、工具链（Windows）
--------------------------------------------------------------------------------

  JDK      17（必需）+ JDK 21（可选，Gradle 自己会挑）。
           ★ RN 0.76 的 gradle 插件给库定了 jvmToolchain(17)。机器上只有 21 时，
             Gradle 会去 api.foojay.io 拖一个 190 MB 的 OpenJDK17 压缩包 ——
             实测那条路只有几 KB/s，卡二十分钟不动，日志里一行都不打，
             看上去像挂死（jstack 一看是 SecureFileDownloader 在读 socket）。
             直接装个 17 最省事；或者在 %USERPROFILE%\.gradle\gradle.properties 里：
                 org.gradle.java.installations.auto-download=false
                 org.gradle.java.installations.paths=<JDK17 路径>,<JDK21 路径>
  Gradle   8.10+（用仓库的 gradlew.bat 就行；系统 gradle 也可以）
  Node     20 LTS+，npm 10；node_modules 必须装（改动要写进 node_modules 里的 RNTP）
  Android  compileSdk 35 / build-tools 35.0.0 / platform 35 / NDK 26.1.10909125 / cmake 3.22.1
           local.properties 里 sdk.dir 指到位（没有就写一个）
  Python   3.8+ 跑 rebuild_carwith.py（只用到 pathlib / hashlib / re，无第三方依赖）

  镜像（可选，但直连 Maven Central 很慢时这是唯一能等的办法）：
    MusicFree 的 root build.gradle 本来就把 aliyun 排在 mavenCentral() 前面，
    但 node_modules 里各库和 RN 插件注入的仓库仍是 repo1.maven.org（实测 ~75 KB/s，
    一个 Kotlin 插件阶段能挂 20 分钟）。在 %USERPROFILE%\.gradle\init.d\mirror.gradle 放：

        import org.gradle.api.artifacts.repositories.MavenArtifactRepository
        def mirror = 'https://maven.aliyun.com/repository/public'
        def slow = ['repo1.maven.org', 'repo.maven.apache.org',
                    'maven-central.storage-download.googleapis.com'] as Set
        def patch = { repos -> repos.all { r ->
            if (r instanceof MavenArtifactRepository && slow.contains(r.url?.host)) { r.url = mirror }
        } }
        settingsEvaluated { s -> patch(s.pluginManagement.repositories)
                            patch(s.dependencyResolutionManagement.repositories) }
        allprojects { p -> patch(p.repositories); patch(p.buildscript?.repositories) }

    ★ 是「改 URL」不是「加仓库」：加在后面没用，Gradle 按声明顺序试，先撞上慢的那个。
    ★ 这一步只影响构建机，不进本文的改动清单，重做产物不受影响。

三、公签
--------------------------------------------------------------------------------

  本文全部改动都签名用仓库自带的 **android/app/debug.keystore**（Android 标准调试密钥，
  公开可知、任何人重做都一样）：

      alias            androiddebugkey
      store/key 密码   android / android
      证书 SHA-256     fac61745dc0903786fb9ede62a962b399f7348f0bb6f899b8332667591033b9c

  做法只有一处（改动 B3）：把 signingConfigs.release 那四行 keystoreProperties 换成
  仓库自带的 debug.keystore。这样：
      · 不需要 keystore.properties、不需要自己生成密钥库，克隆下来直接能出 release 包；
      · 重做出来的 APK 与交付 APK 签名一致，可互相覆盖安装；
      · release 与 debug 同签，装过本包的机器可以直接覆盖本包的 debug 版。
  代价（装之前要知道）：
      · applicationId 仍是 fun.upup.musicfree，签名和官方 release 不同 ⇒
        **手机上装过官方 MusicFree 的要先卸载**，否则 INSTALL_FAILED_UPDATE_INCOMPATIBLE；
      · 别把本包当正式版分发：公钥是公开的秘密，任何人都能做出同签名的包，
        覆盖你的安装。自用/研究用，别拿去替换别人的官方 App。
      · MusicFree 是 **AGPL-3.0**：只自用无所谓，一旦把改后的 APK 给别人（哪怕只发车机群），
        就要同时提供对应源码 —— 本文 + 负载里的 rebuild_carwith.py 与 5 个新文件 + 上游
        基线 tarball，正好凑成「对应源码」，随包附上即可，别只丢 APK。
  验签：
      keytool -list -v -keystore android\app\debug.keystore -storepass android
      apksigner verify --print-certs app-arm64-v8a-release.apk
  ★ debug.keystore 是上游仓库自带的那份（tarball 里就有，sha 不变，本文没动它）；
    上游原本要你在 android/keystore.properties 里填 RELEASE_STORE_FILE 那一套，
    B3 之后 release 档不再读它 —— 你本地真有 keystore.properties 也不会被用上，
    想让 release 用回你自己的密钥，把 B3 的 new 段换回上游四行即可，其余改动不用动。

四、构建
--------------------------------------------------------------------------------

  1) 取源码（二选一，两条取到的是同一棵树）
       git clone https://github.com/maotoumao/MusicFree
       git checkout f82436a7770420f9258b795081120be7cdd5e79c     ← 基线 commit，钉死它
       （或解基线 tarball：sha256 = f27b9be744f7820977776300ed2a726464fb2daaf3672dfe1bcb648ffbcb84c8。tarball == `git archive` 上面那个 commit 的输出，
         实测 diff -r 逐文件无差异，所以两者可互换；别 clone 完停在 master 上就打补丁，
         master 之后每提交一次，锚点命中数就可能变一次）
  2) 装依赖（**必须先装依赖再打补丁**：CarWithLyric.kt 要写进 node_modules 里）
       npm install                # 或 npm ci；几百个包，慢的十几分钟
  3) 打补丁
       python carwith_out\rebuild_carwith.py  .  ..\MusicFree-CarWith-重做说明.txt
       期望输出： 锚点替换 35 处（跳过已打 0 处） + 新文件 5 个
       ★ 重复执行是安全的：锚点已经打过的会 SKIP，不会打第二遍；5 个新文件每次都按负载
         重写（负载就那一份 sha），所以打两遍和打一遍出来的树是同一份，实测第二遍输出
         「锚点替换 0 处（跳过已打 35 处）」。
  4) 构建（在 android 目录里跑，别在外面 —— app/build.gradle 里 getVersion() 读的是
     相对当前工作目录的 ../package.json，站错位置直接 "No such file or directory"）
       cd android
       .\gradlew.bat assembleRelease
  5) 产物
       android\app\build\outputs\apk\release\app-arm64-v8a-release.apk
       bytes = 18185688   sha256 = c896c3548876d979c163e9cbf76a71339f19afa3bc978f5417742e30f49b1446
       同目录还会有 app-universal-release.apk（四 ABI 全带，29469693 B），
       本文的交付件和自检期望值都是上面那个 arm64 分包，别比错文件。

  只出 arm64：B1/B2 把 ABI 收到 arm64-v8a（车机全是 arm64，少三个 ABI 少一半构建量）。
  要恢复上游的四 ABI：把 B1 那行改回 armeabi-v7a,arm64-v8a,x86,x86_64、
  B2 那行改回 include "armeabi-v7a", "arm64-v8a", "x86", "x86_64" 即可，其余不用动。
  ★ 注意 B1 只管 reactNativeArchitectures（RN 那几个 .so 编不编），B2 只管 splits 出哪些分包；
    universal 档两个都不受约束，所以只改 B2 也会出现 universal 带四 ABI 的现象（实测如此）。

  构建期踩坑登记（全是这次实测出来的报错原文，撞到了直接对号入座，别重走）：

    1) `Type mismatch: inferred type is MediaMetadataCompat? but MediaMetadataCompat was
       expected`（:react-native-track-player:compileReleaseKotlin）
       —— ExoPlayer 的 MediaSessionConnector.MediaMetadataProvider.getMetadata 签名是**非空**
       返回，Kotlin SAM 转换会拿可空返回值去对，报的就是这一行。CarWithLyric 里
       providerMetadata() 因此必须收口成非空（播放器没建好时交 EMPTY_METADATA）。
    2) `Unresolved reference: id`（CarWithState.kt 枚举虚拟屏那一段）
       —— android-35 公共桩里 Display 只有 getDisplayId()，**没有 getId()**（javap 实证）；
       写 `d.id` / `d.getId()` 都会挂。同理 getType() 也不在公共桩里，那一层必须反射。
    3) `Inconsistent JVM-target compatibility detected for tasks
       compileReleaseJavaWithJavac (17) and compileReleaseKotlin (21)`
       —— RN 0.76 的 gradle 插件给库定了 jvmToolchain(17)，而 Gradle daemon 跑在 21 上时
       Kotlin 侧跟着 daemon 走 21。解法只有一个：让 **daemon 本身跑在 JDK 17**
       （JAVA_HOME / org.gradle.java.home 指到 17），不要去手改各库的 jvmTarget。
    4) 构建二十分钟不出一行日志，jstack 里是 SecureFileDownloader 在读 socket
       —— foojay 在拖 190 MB 的 OpenJDK17。见「二、工具链」。

       —— 它按**当前工作目录**算相对路径，所以只能在 android/ 里跑，不能用
         `gradle -p android assembleRelease` 站在仓库根上跑。

       —— 十有八九是行尾。上游这棵树里混着 CRLF，实测是这五个：
         android/app/build.gradle、MainApplication.kt、
         src/pages/setting/settingTypes/basicSetting.tsx 与 themeSetting/mode.tsx、

         并去重（read_src/write_src 用 newline="" 原样读写，不做行尾转换），
         自己改锚点时别把这两份合并成一份。

       —— check_edits() 的顺序必须是「先看 new 段在不在 → 在就 SKIP，再看 old 命中几次」，
         反过来写就会把已经打过的当成没打。想验幂等：连着跑两次，第二次应全是 SKIP

  运行期踩坑登记（构建是绿的，装车才炸 —— 这种最难查，实证留在下面）：

    8) 现象：什么开关都没勾、也没连车机，本地随便点一首歌就闪退。
       崩的是 StackOverflowError（主线程），不是歌词键贴错，也不是 Binder 超限。
       根因（javap 实证，extension-mediasession-2.19.0 的 MediaSessionConnector）：
           setMediaMetadataProvider() 的字节码是
               putfield mediaMetadataProvider
               invokevirtual invalidateMediaSessionMetadata()
           而 invalidateMediaSessionMetadata() 里
               invokeinterface MediaMetadataProvider.getMetadata(Player)
           —— 也就是**设 provider 的那一次调用会当场回调新 provider**，不是「挂上去等以后调」。
       于是「在 provider 的取数路径里装 provider」就是一帧咬一帧的自我递归：
           providerMetadata() → 取基值 → 装 provider → 当场回调 providerMetadata() → …
       两个坑叠在一起才会炸：① 递归本身；② 记账写在调用之后
           （conn.setMediaMetadataProvider(p); installedProvider = p）——
           那一次同步回调里 installedProvider 还是 null，「已经装过了」的判断救不了它。
       三条一起才修好，缺一不可：
           a) installProvider() 先 installedProvider = provider 再 conn.setMediaMetadataProvider()，
              挂失败立刻把记账抹掉（下次 publish 重试）；
           b) provider 的回调（providerMetadata/baseOf）里绝不装 provider，只取基值；
              另加 insideProvider 闸门兜同类递归；
           c) publish() 加 dirty 位：从没贴过键（没勾开关、没连过车机）时一次 setMetadata
              都不发、provider 也不装 —— 门控为假时播放路径上**完全不留适配代码的痕迹**，
              只有真贴过键才需要那一次「把键洗掉」的重发。
       ★ 通用教训：凡是「set 一个回调 / provider / listener」的代码，都要先假设它会
         **当场回调一次**。回调里会再次触发 set 的，记账必须在 set 之前；而且加固用的
         try/catch 挡不住 StackOverflowError 之外还有一层——它其实能被 catch（Error 也是
         Throwable），但栈已经快爆了，catch 到的那次只是把崩溃推到更深的递归，别指望它兜底。

  本文**没有**动的东西（前作里有、这里用不上，写清楚免得去找）：
      · 没有动 minifyEnabled（release 本来就没开 R8）——所以反射拿 private 字段是可行的，
        但也正因为如此，哪天有人给这个仓库开了 R8/代码混淆，CarWithLyric 的反射会静默失效

                * mediaMetadataProvider; }
        （本文把这段以「脆弱点」形式登记，不当作改动。）

  ★ 字符串编码 —— 这一条前作帮不上忙，照抄必错，实测结论：

      · assets/index.android.bundle 是 Hermes 字节码，它的字符串表**按字符集分档**：
        纯 ASCII 的串存 UTF-8，**含任何非 ASCII 的串存 UTF-16LE**。
        ⇒ 配置键（ASCII）按 UTF-8 找，中文文案必须按 UTF-16LE 找。
        这次第一版探针全按 UTF-8 写，结果凡是含中文的 needle 一律 FAIL、纯 ASCII 的照常
        PASS（实测口径：`车机投屏歌词（CarWith）` UTF-8 无 / UTF-16LE 有；
        `Car head-unit lyrics (CarWith)` 反过来）；改成两段式后全 PASS。
        py/ps1 现在都是「同一 needle 先试 UTF-8 再试 UTF-16LE，命中就报口径」。

        resources.arsc 那套；前作里的 arsc 补丁在本文**没有对应物**。

        子节匹配，比逐字节循环快两个数量级；py 直接对 bytes 做 `in`。）

         这一步是本文能被公开复现的关键：commit id 钉住了，谁都能取到同一棵树，
         不必依赖我手上那个 tarball 文件。
      2) pristine 里 npm install（node_modules 里的 RNTP 必须是 4.1.1，

#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""python restore.py <本文.txt> [输出目录]   默认 ./carwith_out"""
import hashlib, re, sys
from pathlib import Path

doc = Path(sys.argv[1]).read_text(encoding="utf-8-sig").replace("\r\n", "\n")
out = Path(sys.argv[2] if len(sys.argv) > 2 else "carwith_out")
FENCE = "@" * 3 + "FILE"
END = "@" * 3 + "ENDFILE"
pat = re.compile(FENCE + r" (\S+) \| bytes=(\d+) \| sha256=(\w{16})\n(.*?)\n" + END, re.S)

n = 0
for rel, size, sha, body in pat.findall(doc):
    raw = body.encode("utf-8")
    if len(raw) != int(size) or hashlib.sha256(raw).hexdigest()[:16] != sha:
        sys.exit("FAIL %s：bytes/sha256 对不上（传输过程被改过了）" % rel)
    dst = out / rel
    dst.parent.mkdir(parents=True, exist_ok=True)
    with dst.open("wb") as f:
        f.write(raw)
    print("OK   %7d  %s" % (len(raw), rel))
    n += 1
print("%d 个文件 -> %s" % (n, out.resolve()))
if n == 0:
    sys.exit("没找到负载：确认本文是完整的那份（文末应有 @@@FILE）")

def read_src(path: Path) -> str:
    # newline="" 是为了保住仓库原本的换行符（CRLF/LF 混着），别让它被 universal newlines 改掉
    with path.open("r", encoding="utf-8", newline="") as f:
        return f.read()


def write_src(path: Path, text: str):
    with path.open("w", encoding="utf-8", newline="") as f:
        f.write(text)


def check_edits(root: Path):
    """先全部试算：返回 ({rel: 新文本}, 错误列表)。锚点必须命中一次；已经打过的跳过。"""
    plan, texts, errors, skipped = {}, {}, [], 0
    for tag, rel, old, new in EDITS:
        path = root / rel
        if not path.is_file():
            errors.append("%s：%s 不存在" % (tag, rel))
            continue
        if rel not in texts:
            texts[rel] = read_src(path)
        cur = texts[rel]
        crlf = "\r\n" in cur
        # 换行符跟着仓库走：android/ 那批是 CRLF，src/ 这批是 LF
        pairs = [(old, new)]
        if crlf:
            pair = (old.replace("\r\n", "\n").replace("\n", "\r\n"),
                    new.replace("\r\n", "\n").replace("\n", "\r\n"))
            if pair not in pairs:  # 单行锚点两种写法是一样的，别算两次
                pairs.append(pair)
        # 先认「新文本」：追加式锚点里 old 也是 new 的子串，反过来判会重复打
        if any(cur.count(n) >= 1 for _, n in pairs):
            print("  SKIP %-14s %s" % (tag, rel))
            skipped += 1
            continue
        # 同一段 old 在 CRLF 文件里有两种写法，后者（CRLF）覆盖前者
        uniq = {}
        for o, n in pairs:
            uniq[o] = n
        hit = [(o, n) for o, n in uniq.items() if cur.count(o) == 1]
        if len(hit) == 1:
            o, n = hit[0]
            texts[rel] = cur.replace(o, n, 1)
            plan[rel] = path
        else:
            errors.append(
                "%s：%s 锚点命中 %d 次（要求 1 次，CRLF=%s）"
                % (tag, rel, max(cur.count(o) for o in uniq), crlf)
            )
    return texts, errors, skipped

    fun setConnected(value: Boolean) {
        if (connected == value) return
        connected = value
        publish(true)
    }

    fun setEnabled(value: Boolean) {
        if (enabled == value) return
        enabled = value
        publish(true)
    }

    /** 换曲前、清空队列时把两句收回，避免上一首残留在会话里 */

    /** 由 MusicService 在播放器建好后调一次；provider 的核对在每次发布里 */
    fun attach(audioPlayer: BaseAudioPlayer) {
        player = audioPlayer

    // ------------------------------------------------------------------ 发布

    /**
     * 两条发布路都汇到 decorate()：
     *   1) connector 的 provider —— 上游每次自己发元数据（换曲、封面异步到位）时顺带贴键；
     *   2) 直接 mediaSession.setMetadata() —— 逐句重发用的就是这条，因为上游开了
     *      setMetadataDeduplicationEnabled(true)（按 mediaId 去重，同一首不会再发第二次），
     *      只靠 provider 那条路推不动逐句。
     *
     * force = 状态翻转那几次（连上 / 断开 / 开关），那时就算 decorate 交回的是上游原对象
     * 也要再发一次，否则连着时写过的键收不回来。
     *
     * ★ dirty 那一位是给「总设定」兜底的：从没贴过键（开关没勾、从没连上车）时这里一次
     *   setMetadata 都不发 —— 不装 provider、不碰 connector、不抢上游的发布节奏。
     *   只有真贴过键，才需要那一次「把键洗掉」的重发。上一版没有这一层，attach 一进来就
     *   装了 provider，于是把下面 installProvider 那个递归坑在所有用户面前踩响了。
     */
    private fun publish(force: Boolean) {
        mainHandler.post {
            try {
                val gated = connected && enabled
                var wash = false
                if (!gated) {
                    if (!dirty) return@post      // 干净的：没写过键，也没有键要洗
                    dirty = false                // 只剩这一次「洗键」的重发
                    wash = true
                }
                val p = player ?: return@post
                val s = resolveSession(p) ?: return@post
                if (gated) installProvider(p)    // 装上失败也不要紧，逐句那一路不依赖它
                val base = baseOf(p) ?: return@post
                val decorated = decorate(base)
                if (!force && !wash && decorated === base) return@post
                s.setMetadata(decorated)
            } catch (t: Throwable) {
                // 任何一步失败都只是「这一次车机上没歌词」，不许把播放器带崩
                Log.w(TAG, "publish 跳过（不影响手机播放）", t)
            }
        }
    }

    /**
     * 给 connector 用的那条路：每次上游要元数据时顺贴歌词键。
     * ★ exoplayer 的 MediaMetadataProvider.getMetadata 声明的是**非空**返回值
     *   （Kotlin 侧写 MediaMetadataCompat? 直接编译不过：Type mismatch），
     *   基值取不到时交一份空的，不交 null。
     * ★★ 这里绝不能再走 installProvider：MediaSessionConnector.setMediaMetadataProvider()
     *    会**当场**回调一次新 provider（字节码实证见 installProvider 注释），provider 里
     *    再装 provider 就是一帧咬一帧的自我递归 —— 上一版正是这样把主线程栈打爆的
     *    （现象：什么开关都没勾、本地放歌也闪退，StackOverflowError）。
     *    insideProvider 这道闸门是同类问题的兜底，正常永远走不到它。
     */
    private fun providerMetadata(): MediaMetadataCompat {
        if (insideProvider) {
            val p0 = player ?: return EMPTY_METADATA
            return baseOf(p0) ?: EMPTY_METADATA
        }
        insideProvider = true
        try {
            val p = player ?: return EMPTY_METADATA
            return decorate(baseOf(p)) ?: EMPTY_METADATA
        } catch (t: Throwable) {
            // 这条是 ExoPlayer 在自己线程上调进来的，异常绝不能往外抛
            Log.w(TAG, "provider 跳过（不影响手机播放）", t)
            return EMPTY_METADATA
        } finally {
            insideProvider = false
        }
    }

    private fun decorate(base: MediaMetadataCompat?): MediaMetadataCompat? {
        if (base == null) return null
        // ★ 门控就这一行：没连着或没勾着 ⇒ 原样交回上游那份，元数据逐字不变
        if (!(connected && enabled)) return base

        val nowWhole: String?
        val nowLine: String?
        val nowStatus: Int
        synchronized(LOCK) {
            nowWhole = whole
            nowLine = line
            nowStatus = status
        }

        val cappedWhole = when {
            nowWhole.isNullOrEmpty() -> ""
            nowWhole.length > MAX_WHOLE_CHARS -> ""   // 超限发空串，不截断
            else -> nowWhole
        }
        val hasArtwork = try {
            base.getBitmap(MediaMetadataCompat.METADATA_KEY_ALBUM_ART) != null
        } catch (ignored: Throwable) {
            false
        }

        val b = MediaMetadataCompat.Builder()
        for (key in ALL_KEYS) {
            // 连着车机不发布 MEDIA_URI
            if (key == MediaMetadataCompat.METADATA_KEY_MEDIA_URI) continue
            // 这一份已带到位图时三个 *_URI 一个都不写：车机取图是 description.getIconUri() 优先，
            // 而 iconUri 由那三键级联出来，只断一个还有两个顶上
            if (hasArtwork && key in URI_KEYS) continue
            copyKey(base, b, key, hasArtwork)
        }

        b.putString(KEY_WHOLE, cappedWhole)
        b.putString(KEY_FRAMEWORK_LYRICS, cappedWhole)
        b.putString(KEY_LINE, nowLine ?: "")
        // 整首超限发空串时，只要当前句还在就走「有词 + 兜底句」，别让车机按无词把这句抹掉
        val lyricUsable = nowStatus == STATUS_HAS_LYRIC &&
            (cappedWhole.isNotEmpty() || !nowLine.isNullOrEmpty())
        b.putString(KEY_STATUS, if (lyricUsable) "0" else STATUS_NO_LYRIC.toString())
        // 记一笔「这份元数据上贴过键」—— 之后断开/关开关才需要那一次把键洗掉的重发
        dirty = true
        return b.build()
    }

    private fun copyKey(
        base: MediaMetadataCompat,
        b: MediaMetadataCompat.Builder,
        key: String,
        hasArtwork: Boolean,
    ) {
        if (hasArtwork && key in EXTRA_BITMAPS) return
        try {
            val cs = base.getText(key)
            if (cs != null) {
                b.putString(key, cs.toString())
                return
            }
        } catch (ignored: Throwable) {
        }
        try {
            val v = base.getLong(key)
            if (v != 0L) {
                b.putLong(key, v)
                return
            }
        } catch (ignored: Throwable) {
        }
        try {
            val bmp = base.getBitmap(key)
            if (bmp != null) {
                b.putBitmap(key, bmp)
                return
            }
        } catch (ignored: Throwable) {
        }
        try {
            val r = base.getRating(key)
            if (r != null) {
                b.putRating(key, r)
            }
        } catch (ignored: Throwable) {
        }
    }

    /** BaseAudioPlayer.mediaSession（private val）。release 没开 R8（minifyEnabled=false），字段名逐字保留 */
    private fun resolveSession(p: BaseAudioPlayer): MediaSessionCompat? {
        session?.let { return it }
        val found = readPrivate(p, "mediaSession") as? MediaSessionCompat ?: return null
        session = found
        return found
    }

    private fun resolveConnector(p: BaseAudioPlayer): MediaSessionConnector? {
        connector?.let { return it }
        val found =
            readPrivate(p, "mediaSessionConnector") as? MediaSessionConnector ?: return null
        connector = found
        return found
    }

    /** kotlinaudio 那两个成员是 private val，只能反射取；沿父类链找，免得它挪个声明位置就断 */
    private fun readPrivate(target: Any, name: String): Any? {
        var c: Class<*>? = target.javaClass
        while (c != null) {
            try {
                val f: Field = c.getDeclaredField(name)
                f.isAccessible = true
                return f.get(target)
            } catch (ignored: Throwable) {
            }
            c = c.superclass
        }
        return null
    }

    /**
     * 取上游那份「干净基值」。
     * ★★ 这里绝对不装 provider —— 装 provider 是 publish 里 gated 那一支的活。
     *   provider 的回调又要取基值，一旦这里回头去装 provider 就是自我递归（见 installProvider）。
     */
    private fun baseOf(p: BaseAudioPlayer): MediaMetadataCompat? {
        return try {
            p.notificationManager.getMediaMetadataCompat()
        } catch (ignored: Throwable) {
            null
        }
    }

    /**
     * 上游的 provider 是在 BaseAudioPlayer init 的一个 coroutine 里设的
     * （mediaSessionConnector.setMediaMetadataProvider { notificationManager.getMediaMetadataCompat() }），
     * 我们的 attach 可能跑在它前面把它顶掉，所以每次要贴键前核一次身份。
     *
     * ★★ 记账必须在调用之前：MediaSessionConnector.setMediaMetadataProvider() 不是单纯赋值，
     *   字节码是 putfield → invalidateMediaSessionMetadata() → invokeinterface getMetadata(Player)，
     *   也就是**当场回调一次新 provider**。上一版写成「先 conn.setMediaMetadataProvider(provider)
     *   再 installedProvider = provider」，那一次同步回调里 installedProvider 还是 null、
     *   current 也还是旧的，于是又走回装 provider 那一路 —— provider 装 provider，一帧咬一帧，
     *   直接把主线程栈打爆（StackOverflowError，现象是「什么开关都没勾、本地点一下就闪退」）。
     *   所以这里先把自己记上、再挂上去；挂失败就立刻把记账抹掉，下次 publish 会重试。
     */
    private fun installProvider(p: BaseAudioPlayer): Boolean {
        val conn = resolveConnector(p) ?: return false
        val current = try {
            readPrivate(conn, "mediaMetadataProvider")
        } catch (ignored: Throwable) {
            null
        }
        if (current != null && current === installedProvider) return true
        val provider = MediaSessionConnector.MediaMetadataProvider { _: Player ->
            providerMetadata()
        }
        installedProvider = provider
        return try {
            conn.setMediaMetadataProvider(provider)
            true
        } catch (t: Throwable) {
            installedProvider = null
            Log.w(TAG, "provider 装不上（已忽略，逐句那一路不受影响）", t)
            false
        }
    }
}

/** [mm:ss.xx] —— 车机侧 LRC 解析只认这个格式 */
function timeToLrctime(sec: number): string {
    const totalCs = Math.max(0, Math.round(sec * 100));
    const mm = Math.floor(totalCs / 6000);
    const ss = Math.floor((totalCs % 6000) / 100);
    const cs = totalCs % 100;
    return `[${String(mm).padStart(2, "0")}:${String(ss).padStart(2, "0")}.${String(
        cs,
    ).padStart(2, "0")}]`;
}

/**

 * 时间戳要**带上歌词偏移**：parser.getPosition 里是 `position - meta.offset`，
 * 也就是说 item.time 是「不含偏移」的原始时间，车机拿去和真实播放位置比要加回去。
 * 只出主行，不带译文（车机一屏一行，带译文会把行高挤掉）。
 *
 * 整首按 parser 缓存：逐句那一路每秒来一次，几百行 join 一次是白烧 CPU
 * （偏移一改 lyricManager 就 new 一个新 parser，缓存自然失效，不用另设 invalidate）。
 */

function buildWholeLyric(parser: LyricParser | null | undefined): string {
    if (!parser) return "";
    if (parser === wholeCacheParser) return wholeCache;
    const items = parser.getLyricItems?.() ?? [];
    const offset = Number(parser.getMeta?.()?.offset ?? 0) || 0;
    const whole = items.length
        ? items
            .map(item => `${timeToLrctime(item.time + offset)} ${item.lrc ?? ""}`)
            .join("\r\n")
        : "";
    wholeCacheParser = parser;
    wholeCache = whole;
    return whole;
}
